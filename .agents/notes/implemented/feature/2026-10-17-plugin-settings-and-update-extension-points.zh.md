# Agent Note: 插件设置与更新扩展点

Status: implemented

[English](2026-10-17-plugin-settings-and-update-extension-points.md) | 中文

## 问题

公司插件检查更新需要逐一进入详情，管理入口占用主侧栏。既有已安装卡片缺少版本与更新扩展位置。重做官方页面或注入 DOM 修改会让行为和外观脱离上游。

## 决策

`DSH-001` 保留官方页面、图标、按钮及安装配置控制器。已安装组合包排在官方分组前面，优先显示公司插件及其更新。同一页面占据最后一个 `settings.section`，`pluginNavigation.openBundle` 通过设置壳的 `settingsNavigation.open` 打开详情，不选择工作区主面板。设置入口使用已有官方插件图标，原只读插件清单保持独立。

已安装卡片显示版本。标记和操作 slot 接收已有组合包 subject，组工具 slot 接收已安装包引用。操作、开关与内容共用一行。手动刷新等待列表读取和 `plugins.list.tools` 登记的回调。公司元信息、发行来源、更新事务状态及策略继续归公司插件。

桌面产品主 frame 获得无参数重启操作。原任务确认可取消，重复请求共享同一决定。确认后安排重启，沿原流程收尾 Host。其他文档和子 frame 仍受原调用来源限制。Web 组合不会获得桌面重启操作。

## 考虑过的替代方案

**新建插件页。** 用户已否决。官方页面仍是唯一管理器。

**DOM 补丁或安装包字符串替换。** 不采用。它们会让源码不能完整表达实际布局与导航。

**把公司更新策略放入 Core。** 不采用。Core 提供呈现和生命周期能力，GEA 持有签名更新事务及恢复。

Slot 合同说明以双语保存在同目录的 `slot-contract.slots.json`。原客户端目录生成器读取它，并拒绝未知 slot、缺失译文和重复文档来源；没有说明的 slot 仍被原完整性检查拒绝。

## 影响

Core 保留必要列表扩展位、设置导航与桌面生命周期操作。贡献者通过这些能力实现公司行为。即使本地化标题去掉个人账号前缀，安装和查找仍使用原包标识。

## 验证

既有包测试覆盖注册、销毁、设置顺序、手动刷新合并、原安装行为及详情导航。桌面测试覆盖来源拒绝、重复请求、取消后无延迟重启及原 Host 收尾。公司浏览器和真实包安装、重启验证由配套实现负责；这些检查不代表频道发布或正式客户端验收。
