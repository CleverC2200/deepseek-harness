# Agent Note: 桌面更新元数据检查

Status: implemented

[English](2026-11-04-desktop-update-check.md) | 中文

## 问题

公司插件协调更新需要先确定原生更新目标，再缓存其插件组合。打开原生更新提示可能已经开始下载。

## 决策

`DSH-005` 为现有产品 preload 更新接口增加只检查版本的动作。它复用既有调度和协调器，验证自有顶层页面，并返回现有状态投影。更新地址及安装权限仍归主进程。调用者可在打开更新提示时指定已确认版本，目标变化时拒绝继续。

## 考虑过的替代方案

用更新提示发现版本，不能保证准备发生在下载之前。另写更新源读取器会重复原生版本选择。

## 影响

检查动作不下载或安装。既有任务与重启确认继续有效。公司插件及启动安装仍归 GEA。

## 验证与退场

Preload 和启动测试覆盖通道、页面归属、旧目标拒绝，以及检查时不下载、不安装、不出现确认框。采用的原生更新接口提供等效准备动作后，删除这项公司差异。
