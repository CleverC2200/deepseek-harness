# Agent Note: 公司 Core 源码维护模式

Status: implemented

[English](2026-10-17-company-core-source-maintenance.md) | 中文

## 问题

公司桌面功能有时超出现有上游插件扩展点。这些源码改动需要长期维护归属，并在上游升级后仍能查到原因，不能依靠源码中的公司修改历史或某个聊天账号。

## 决策

本维护决策编号为 `DSH-000`。公司通过现有 GitHub fork `CleverC2200/deepseek-harness` 维护 Core 源码。`deepseek-ai/deepseek-harness` 继续作为上游比较来源。这是已采用的维护约定，不代表待做的插件设置功能已经实现或发布。确定此 fork 不会自动升级它的默认分支，也不把其中的旧源码确定为下一版产品基线。

公司改动优先使用现有扩展点。确实缺少扩展点时，采用最小完整的 Core 改动，并在同一项改动中更新受影响调用者与验证。业务身份、凭据、授权和接口日志继续归 GEA，业务页面继续归 Workbench。增加 Core 接口不改变这些职责。

代码通过命名和结构表达行为。新的公司改动不新增解释性源码注释，保留已有必要 API 合同。提交信息解释具体改动。对应 Agent Note 记录目的、取舍、职责、必要验证及删除条件。不另建平行的 ADR 目录或人工维护的补丁副本。

每项独立维护的公司差异采用稳定编号，例如 `DSH-001`。对应 Agent Note 写明该编号，实现及修正提交携带 `Company-Change: DSH-001`。Git 和 PR 保存实际文件差异与版本。记录不重复代码、行号或人工维护的 rebase 后提交编号列表。编号只帮助查询，不作为授权或兼容校验。

### 基线与升级

正式实施前，本票分别冻结实际官方仓库、发行引用、完整提交编号与公司源码版本。已有任务整合清单继续负责各自候选输入；本约定不另建竞争性的全局基线登记。最终构建回执在所标识的源码提交之外，记录官方基线、实际公司源码版本、相关插件版本、产物摘要与验证证据。

升级上游时使用隔离候选，只迁移仍需保留的公司改动，并通过 `git range-diff` 比较迁移前后的提交序列。行为测试和实际安装产物检查分别留证。已发布来源的引用保持原指向。上游覆盖公司需求后，先核原验收条件，再删除重复实现；对应记录说明接替来源和删除原因。

源码 revert 不会恢复或降级 Session 数据、草稿、预设及持久格式。数据兼容单独验证。受保护的官方 checkout 和当前正式客户端不作为开发目标；发布与业务写入继续遵循各自授权。

### 查询某项差异

```sh
git log --all --grep='Company-Change: DSH-001'
git diff <official-base> <company-source> --stat
git range-diff <old-base>..<old-source> <new-base>..<new-source>
```

这些命令说明 Git 查询方式，不证明升级或产品验收已经执行。`range-diff` 辅助人工审查，不代替测试。

## 考虑过的替代方案

**通过源码注释保存修改历史。** 不采用。这样会把当前行为与公司修改历史混在一起，增加日常读取代码所需的上下文。

**第二套补丁队列或安装包字符串替换。** 不作为维护权威。它们重复源码差异，也会让审查过的源码与实际运行代码脱节。需要交付补丁时，可从固定 Git 基线导出。

**独立决策目录或个人聊天记忆。** 不作为主要记录。此 fork 已有 Agent Notes，维护者需要在源码旁找到决策，不依赖账号或聊天历史。

## 影响

公司 Core 有唯一源码维护归属，后续改动可以与冻结的上游基线比较，并查到长期保留的原因。实现位置变化时更新对应记录，决策被替代时按现有 Agent Note 生命周期保留依据。这会增加必要的记录与上游适配工作，不新增治理服务，也不改变原发布检查。

## 尚未实施

插件更新和设置导航仍是独立的实施工作。已确认的界面边界保留完整官方插件顺序、布局、图标和顶部刷新、添加按钮。官方插件在上，已安装插件在下。只扩展已安装插件的更新信息与操作。插件管理从主侧栏移到设置最后一项，既有 GEA 接口日志页也补设置入口。本约定记录不包含这些功能的源码补丁、实际运行验收或客户端发布。
